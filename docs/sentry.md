# NumVault — Sentry Integration Guide

## Overview

Sentry is integrated into NumVault via `@sentry/react-native`. It provides crash monitoring, error tracking, performance tracing, Session Replay, structured event breadcrumbs, and custom metrics for all key user journeys.

---

## Environments

| Environment | Value | Sentry traces sample rate | Replay |
|---|---|---|---|
| Development (`__DEV__ = true`) | `development` | 100% | Disabled |
| Production | `production` | 20% | 10% sessions, 100% on error |

---

## Release Strategy

- Release name is automatically generated by the `@sentry/react-native/expo` config plugin using `expo.version` from `app.json` (e.g. `ng.numvault.app@1.0.4+15`).
- **Do not manually set `release` in `Sentry.init()`** — the plugin injects it at build time.
- Every AAB/IPA build will produce a uniquely identified release in Sentry tied to the version + versionCode.

---

## Source Maps and Native Symbols

- The `@sentry/react-native` SDK is initialised directly in `app/_layout.tsx` without the `@sentry/react-native/expo` Expo config plugin (the plugin triggers a postinstall script that requires `expo` to be resolvable at install time, which is incompatible with the OnSpace build environment).
- Source maps can be uploaded manually via the Sentry CLI after each EAS build if symbolication is needed.
- Native debug symbols (dSYMs / ProGuard) must be uploaded separately via `sentry-cli upload-dif`.

## Required Environment Variables

### In `.env` (client-side, safe to include in app bundle):
```
EXPO_PUBLIC_SENTRY_DSN=https://YOUR_DSN_HERE@oXXXXXX.ingest.sentry.io/XXXXXXX
```

### In EAS build secrets (never committed to git):
```
SENTRY_AUTH_TOKEN=your_sentry_auth_token_for_source_map_uploads
```

To set the EAS secret:
```bash
eas secret:create --scope project --name SENTRY_AUTH_TOKEN --value your_token
```

To get a Sentry auth token:
1. Go to https://sentry.io/settings/account/api/auth-tokens/
2. Create a token with `project:releases` and `org:read` scopes.

## Session Replay Privacy Configuration

Session Replay is configured with **maximum privacy protection**:

```typescript
Sentry.mobileReplayIntegration({
  maskAllText: true,    // ALL text is masked — passwords, OTPs, numbers, amounts
  maskAllImages: true,  // ALL images are blocked
})
```

This means no readable text from any screen will appear in Sentry replays. This is intentional — NumVault handles sensitive payment and SMS data. Adjust only if a specific non-sensitive screen requires unmasked replay, and document the change here.

---

## Privacy Protections

The following data is **never** sent to Sentry:

- Passwords and password-related inputs
- OTP codes
- Paystack authorization codes or secrets
- Card numbers, CVV, expiry dates
- Wallet credentials or API keys
- Purchased temporary phone numbers (order_id is used instead)
- User emails (only internal `user_id` is set in Sentry user context)

The `beforeSend` hook in `app/_layout.tsx` strips any event extra/context key whose name contains: `password`, `otp`, `token`, `auth_code`, `card`, `cvv`, `secret`.

The `beforeBreadcrumb` hook drops console breadcrumbs containing those keywords.

---

## User Context Management

- **On login/signup completion**: `setSentryUser(userId)` — sets only the internal user ID
- **On logout**: `clearSentryUser()` — removes all user context from Sentry
- **On account deletion**: `clearSentryUser()` — called before navigating away

## Testing Sentry

### Test a JavaScript error
Temporarily add to any screen (remove after testing):
```typescript
import * as Sentry from '@sentry/react-native';

// In a button handler:
Sentry.captureException(new Error('[NumVault TEST] Manual Sentry test error'));
```

### Test a navigation transaction
Navigate between tabs — Sentry's navigation instrumentation auto-captures route changes.

### Verify in Sentry dashboard
1. Open https://sentry.io/organizations/supremeanalytics/projects/numvault/
2. Check **Issues** for the test error
3. Check **Performance** → **Transactions** for navigation events
4. Check **Replays** for session recordings (production only)

## Adding New Sentry Events (for future developers)

1. Add a new `track*` or `capture*` function to `services/sentryService.ts`
2. Use `Sentry.addBreadcrumb()` for user-journey steps (not errors)
3. Use `Sentry.metrics.increment()` for countable outcomes
4. Use `Sentry.metrics.distribution()` for numeric distributions (e.g. amounts)
5. Use `captureError(error, context)` for caught exceptions with non-sensitive context
6. **Never include sensitive data** in breadcrumb `data`, metric tags, or exception context
7. Test the event in development before deploying

## Important: Android AAB Build Compatibility

The Sentry integration preserves all existing Android build fixes:

- `assetBundlePatterns` remains the explicit list (no wildcard `**/*`)
- `removeStaleOnboardingAssets` Gradle plugin remains intact
- The Sentry `@sentry/react-native/expo` plugin is listed **after** `removeStaleOnboardingAssets` in `app.json` to avoid ordering conflicts
- `metro.config.js` uses only the Sentry Metro transformer plugin (no custom resolvers/transformers that could break the hermesc chain)
- `babel.config.js` preserves the `nv-build-9` cache-bust invalidation with Sentry's Babel plugin added

The Sentry build plugin does **not** inject duplicate Gradle tasks. It handles source-map generation as part of the standard Metro bundle pipeline.
